## 1. Jolt fundamentals: architecture, bodies, shapes, ghost collisions, queries

### Takeaway
Jolt is a conventional rigid-body engine (bodies + shapes, sequential-impulse solver, islands, sleeping) whose special
property is concurrency: a mostly lock-free quad-tree broad phase per broad-phase layer, body locks, and queries that can
run from many threads. For a character controller the parts that matter are the query API (CastRay / CollideShape /
CastShape with back-face, active-edge and max-separation settings) and the two ghost-collision mitigations (active edges
baked into mesh shapes; run-time "enhanced internal edge removal" that only works inside one body).

### Cited Findings
Bodies and simulation
- Body types: static (not moving or simulating), dynamic (moved by forces), kinematic (moved by velocities only). Static bodies have no MotionProperties unless `mAllowDynamicOrKinematic` is set. Jolt master. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Solver: "a Sequential Impulse solver with warm starting" (Erin Catto's method). `PhysicsSystem::Update` spreads work over a `JobSystem`. A physics step can be split into several collision steps (60 Hz with 2 collision steps = collision + integration at 1/120 s twice). "In general, the system is stable when running at 60 Hz with 1 collision step." — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Velocity solve iterates until impulses are too small or `PhysicsSettings::mNumVelocitySteps` is reached; position solve (fixes drift) until corrections are too small or `mNumPositionSteps` is reached. Jolt defaults: `mNumVelocitySteps = 10`, `mNumPositionSteps = 2`, `mBaumgarte = 0.2`, `mSpeculativeContactDistance = 0.02`, `mPenetrationSlop = 0.02`, `mLinearCastThreshold = 0.75`, `mLinearCastMaxPenetration = 0.25`, `mTimeBeforeSleep = 0.5`, `mPointVelocitySleepThreshold = 0.03`, `mMinVelocityForRestitution = 1.0`. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [PhysicsSettings.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/PhysicsSettings.h)
- Islands: sets of dynamic bodies in contact or joined by constraints; rebuilt from scratch every step (lock-free, O(N)); a whole island is put to sleep when all its bodies are at rest. Sleeping bodies still detect collisions with awake bodies. Removing a body does not wake neighbours; `Body::SetLinearVelocity` does not wake a body (`BodyInterface::SetLinearVelocity` does). Sleep test tracks 3 bounding spheres of points on the body over time. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Large islands (more contacts+constraints than `LargeIslandSplitter::cLargeIslandTreshold`) are split into groups that touch disjoint bodies so they can be solved in parallel. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Integrator is symplectic Euler (stated in the motor section: "Because Jolt Physics uses a Symplectic Euler integrator, there will still be a small amount of damping when damping is 0"). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Determinism: deterministic if API calls are made in exactly the same order and the same binary is used; cross-platform determinism needs the `CROSS_PLATFORM_DETERMINISTIC` CMake option ("approximately 8% slower"). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Threading rules: locking and non-locking body interfaces; bodies cannot be read/written while `PhysicsSystem::Update` runs; contact / activation / step callbacks are called from multiple threads inside Update and may only read bodies. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Motion quality: default `Discrete` (collision detection at step start, then free movement; "Fast and small objects can easily 'tunnel' through thin objects"). `LinearCast` adds a CastShape after the new position is known and places the body back at the hit ("time stealing": the body appears to move slower for one step). LinearCast rotates the object fully first, so fast-rotating long objects can still pass through. CCD is only scheduled when movement exceeds a threshold based on the shape's inner radius. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Sensors: bodies that report contacts but do not resolve them; a static sensor only detects active bodies; sensors only use Discrete motion quality; to see static bodies set `mCollideKinematicVsNonDynamic` (warning: heavy against large meshes / height fields). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)

Broad phase, narrow phase, layers
- Broad phase is `BroadPhaseQuadTree`: an AABB tree with 4 children per node (4 children are tested per SIMD instruction). When a body moves, nodes from root to leaf are expanded lock-free; a new tight tree is built in the background during the next step and swapped in. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [GDC 2022 notes PDF](https://jrouwe.nl/architectingjolt/ArchitectingJoltPhysics_Rouwe_Jorrit_Notes.pdf)
- One quad tree per `BroadPhaseLayer`; standard setup is at least 2 (static, dynamic); "you should only have a few broad phase layers". Each body is in one `ObjectLayer` (16 or 32 bit); filters: `BroadPhaseLayerInterface` (object layer -> broad-phase layer), `ObjectVsBroadPhaseLayerFilter`, `ObjectLayerPairFilter`. Filter order: broad-phase layer -> object layer -> GroupFilter (simulation only; e.g. `GroupFilterTable` for ragdolls) / BodyFilter (queries) -> shape filter -> ContactListener (most expensive place to reject). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Narrow-phase queries first query the broad phase, then take a `TransformedShape` snapshot under a short body lock and do the bulk of the work outside the lock; all narrow-phase queries use GJK and EPA. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)

Shapes
- Shapes "in order of computational complexity": Sphere, Box, Capsule, TaperedCapsule, Cylinder ("cylinders are the least stable of all shapes, so use another shape if possible"), TaperedCylinder, ConvexHull, Triangle, Plane, StaticCompound (tree, immutable), MutableCompound (list, changeable at run time), Mesh ("mostly used for static geometry"), HeightField (NxN, body must be static), Empty. Decorators: ScaledShape, RotatedTranslatedShape, OffsetCenterOfMassShape. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Convex radius: every convex shape is first shrunk by the convex radius and then inflated by it, giving rounded edges without growing the shape. "A larger convex radius results in better performance but a less accurate simulation. A convex radius of 0 is allowed." — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Mesh shapes "don't have a clear inside/outside so a mesh is only considered to be colliding when one of its triangles intersect with the other object. This can result in objects getting stuck inside the mesh without knowing which way is out." Dynamic/kinematic meshes cannot collide with other mesh or height-field shapes. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- `SubShapeID` is a 32-bit path to a leaf (triangle / compound child) returned with every collision result. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)

Ghost collisions
- Definition: a body sliding over another hits an internal edge (triangle edge in a mesh, or the seam between two boxes) and stops or jumps. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Active edges: MeshShape and HeightFieldShape mark edges at construction. Hitting an inactive edge returns the face normal; hitting an active edge can return a normal between the two faces. Threshold `mActiveEdgeCosThresholdAngle`, default 5 degrees in Jolt; "making this bigger reduces the amount of ghost collisions but can create simulation artifacts if you hit the edge straight on". — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Enhanced internal edge removal (`BodyCreationSettings::mEnhancedInternalEdgeRemoval`, added in Jolt v5.0.0): run-time check; only works if edges are shared (different-sized neighbours or T-junction triangles still ghost) and the shared edges are in the same shape/body (use a StaticCompoundShape to merge boxes). Usable in custom queries via `InternalEdgeRemovingCollector`. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- `EActiveEdgeMode`: `CollideOnlyWithActive` (default; "For physics simulation, this gives less ghost collisions") or `CollideWithAll`. With CollideOnlyWithActive, `mActiveEdgeMovementDirection` can be given: on an inactive edge the triangle normal is chosen "only if it impedes the movement less than with the calculated penetration depth". — [ActiveEdgeMode.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/ActiveEdgeMode.h); [CollideShape.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/CollideShape.h)

Queries
- Query entry points: ray (`NarrowPhaseQuery::CastRay`), static overlap (`CollideShape`), sweep (`CastShape`), point containment (`CollidePoint`); each also exists on BroadPhaseQuery (AABB only), TransformedShape (one body) and Shape. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Ray casts against triangle meshes "can miss when a ray passes exactly along an edge shared by two triangles because of floating-point rounding"; Jolt's advice is a small shape cast (e.g. a sphere) or extra rays with slightly offset origins, taking the nearest hit. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- `RayCastSettings`: `mBackFaceModeTriangles` and `mBackFaceModeConvex` both default `IgnoreBackFaces`; `mTreatConvexAsSolid` default true ("a ray starting inside a convex shape will generate a hit at fraction 0"). — [RayCast.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/RayCast.h)
- `CollideShapeSettings`: `mMaxSeparationDistance` (default 0; when > 0 nearby non-touching contacts are returned and `mPenetrationDepth` becomes negative = separation), `mBackFaceMode` default `IgnoreBackFaces`, `mCollectFacesMode` default NoFaces, plus the active-edge fields above. `CollideShapeResult` gives contact point on each shape, `mPenetrationAxis` ("Direction to move shape 2 out of collision along the shortest path"; `-mPenetrationAxis.Normalized()` is the contact normal), `mPenetrationDepth`, sub-shape ids, body id, optional faces. — [CollideShape.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/CollideShape.h)
- `ShapeCastSettings`: `mBackFaceModeTriangles` / `mBackFaceModeConvex` default IgnoreBackFaces, `mUseShrunkenShapeAndConvexRadius` default false, `mReturnDeepestPoint` default false ("When true, and the shape is intersecting at the beginning of the cast (fraction = 0) then this will calculate the deepest penetration point (costing additional CPU time)"). Result adds `mFraction` and `mIsBackFaceHit`; at fraction 0 the "contact normal" field is a penetration-depth vector. — [ShapeCast.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/ShapeCast.h)
- `EBackFaceMode`: `IgnoreBackFaces` or `CollideWithBackFaces`. — [BackFaceMode.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Collision/BackFaceMode.h)

### Inferences
- Collide-shape versus cast-shape: CollideShape answers "what overlaps (or is within max-separation of) this pose, how deep, along which axis"; CastShape answers "at what fraction does a sweep first touch". Only CollideShape gives a penetration depth for a resting pose and a "nearly touching" margin; only CastShape gives a time of impact. A controller needs both (sweep to move, collide to recover/classify) - which is exactly how both CharacterVirtual and Godot's `body_test_motion` are built (sections 2 and 3).
- Because EPA degrades when two curved shapes are exactly concentric (see section 5), query shapes should not be placed at exactly the same centre as a body's sphere/capsule.

### Gaps
- No Jolt page was fetched that documents collectors (AllHit / ClosestHit / AnyHit) by name; only their use in Godot's module was seen. Not verified from Jolt docs.
- The GDC 2022 notes were only skimmed by keyword; they contain little on characters or ragdolls (see section 6).

## 2. Jolt character classes: Character versus CharacterVirtual

### Takeaway
`Character` is a rigid body with rotation locked (cheap, physically simulated, recommended by Jolt for simple AI);
`CharacterVirtual` is not a body at all - it moves by narrow-phase queries when the game calls its update, and carries
the stair-stepping, floor-sticking, slope, moving-platform and pushing logic. Jolt itself says a player usually wants the
virtual one. None of this is reachable from Godot script (section 3).

### Cited Findings
- `Character`: "essentially a rigid body that has been configured to only allow translation"; simulated with other bodies; "usually not the best solution for a player as the player usually requires a lot of behavior that is non-physical"; "cheap so it is recommended for e.g. simple AI characters". `Character::PostSimulation(inMaxSeparationDistance)` must be called after every `PhysicsSystem::Update` to update ground contacts. Defaults: mass 80 kg, friction 0.2, gravity factor 1, DOFs = translation X/Y/Z only. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [Character.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/Character.h)
- `CharacterVirtual`: "implemented using collision detection functionality only (through NarrowPhaseQuery) and is simulated when CharacterVirtual::Update is called"; not added to the world, invisible to rigid bodies, interacts by applying impulses during its update. Documented artefact: "the character slightly hovering above an elevator going down, because the characters moves at a different time than the other rigid bodies". Benefit: update happens when the game wants; several can update concurrently. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Extra functionality listed for CharacterVirtual: sliding along walls; elevators and moving platforms; enhanced steep-slope detection (standing in a funnel whose sides are too steep is not treated as too steep); stair stepping and sticking to the ground through `ExtendedUpdate`; a local coordinate system (walking inside a moving ship). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Consequences of not being a body: callbacks go through `CharacterContactListener`; sensor contacts too; character-vs-character needs `CharacterVsCharacterCollision` (the supplied `CharacterVsCharacterCollisionSimple` is brute force and "not thread safe"); normal ray casts do not hit it. Hybrid: `CharacterVirtualSettings::mInnerBodyShape` creates an inner rigid body that follows it, so sensors, regular queries and LinearCast bodies see it. (Inner body and character-vs-character added in Jolt v5.1.0.) — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- Base settings (both classes): `mUp` = +Y; `mSupportingVolume` plane (contacts behind it can support the character; default accepts any); `mMaxSlopeAngle` = 50 degrees; `mEnhancedInternalEdgeRemoval` = false (added v5.1.0, "more expensive but makes bodies move smoother over a mesh with convex edges"); `mShape` "Usually this is a capsule, make sure the shape is made so that the bottom of the shape is at (0, 0, 0)". — [CharacterBase.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterBase.h)
- Ground state enum: `OnGround` (can move freely), `OnSteepGround` (slope too steep, "caller should start applying downward velocity if sliding from the slope is desired"), `NotSupported` (touching but not supported, should fall), `InAir`. Accessors: ground position, normal, velocity, material, body id, sub-shape id, user data. `IsSlopeTooSteep(normal)` = `normal.Dot(up) < cos(maxSlope)`. — [CharacterBase.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterBase.h)
- CharacterVirtual settings and defaults: `mMass` 70 kg ("Used to push down objects with gravity when the character is standing on top"); `mMaxStrength` 100 N (max push force); `mBackFaceMode` CollideWithBackFaces; `mPredictiveContactDistance` 0.1 m ("A value of 0 will most likely cause the character to get stuck as it cannot properly calculate a sliding direction anymore. A value that's too high will cause ghost collisions."); `mMaxCollisionIterations` 5; `mMaxConstraintIterations` 15; `mMinTimeRemaining` 1e-4; `mCollisionTolerance` 1e-3 ("How far we're willing to penetrate geometry"); `mCharacterPadding` 0.02 m ("How far we try to stay away from the geometry, this ensures that the sweep will hit as little as possible lowering the collision cost and reducing the risk of getting stuck"); `mMaxNumHits` 256; `mHitReductionCosMaxAngle` 0.999 (about 2.5 degrees); `mPenetrationRecoverySpeed` 1.0 (0 = nothing, 1 = all in one update). — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- `Update(dt, gravity, filters...)`: moves by current velocity; "it's your own responsibility to apply gravity to the character velocity"; the gravity argument is only used to press down on what the character stands on. Surface materials (ice) are emulated by reading the ground material and changing velocity / max slope each frame. — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- `CanWalkStairs(desiredVelocity)`: true if the character moved into a too-steep slope (e.g. a vertical wall). `WalkStairs(dt, stepUp, stepForward, stepForwardTest, stepDownExtra, ...)`: "cast up, forward and down again to try to find a valid position". `inStepForwardTest` exists because "When running at a high frequency, inStepForward can be very small and it's likely that you hit the side of the stairs on the way down. This could produce a normal that violates the max slope angle. If this happens, we test again using this distance from the up position to see if we find a valid slope." — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- `StickToFloor(stepDown, ...)`: "when a character is on a small step and starts moving horizontally, the character will lose contact with the floor because the initial vertical velocity is zero while the horizontal velocity is quite high"; it does an extra downward collision check and projects the character onto the floor if found within the distance. — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- `ExtendedUpdate` = Update + StickToFloor + WalkStairs ("serves as an example of how these functions could be combined"). Default `ExtendedUpdateSettings`: stick-to-floor step down (0, -0.5, 0); walk-stairs step up (0, 0.4, 0); min step forward 0.02; step-forward test 0.15; cos angle forward contact cos(75 degrees); step-down extra zero. Velocity recipe before calling: on ground and not moving away: `GetGroundVelocity() + horizontal input + optional jump + dt * gravity`; else `current vertical velocity + horizontal input + dt * gravity`. — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- Other functions: `CancelVelocityTowardsSteepSlopes`; `RefreshContacts` (after a teleport); `UpdateGroundVelocity` (cheap re-read of the ground body's velocity, no collision detection); `SetShape(shape, maxPenetrationDepth, ...)` (crouch/stance; when max penetration is not FLT_MAX it checks the new shape for collision first and returns false if it does not fit); `SetInnerBodyShape`; `StartTrackingContactChanges` / `FinishTrackingContactChanges`; `GetActiveContacts`; `GetMaxHitsExceeded` ("find areas that have too complex geometry for the character to navigate properly"). — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h)
- Listener callbacks: `OnAdjustBodyVelocity` (change the velocity of a body as seen by the character - conveyor belts), `OnContactValidate`, `OnContactAdded` / `OnContactPersisted` / `OnContactRemoved` (persisted/removed added v5.3.0), `OnContactSolve` (override the slide velocity, "e.g. by preventing sliding along certain surfaces"), and character-vs-character equivalents. `CharacterContactSettings`: `mCanPushCharacter`, `mCanReceiveImpulses`. — [CharacterVirtual.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Character/CharacterVirtual.h); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- Shape guidance from Jolt: controllers "are usually used to represent the player as a simple capsule or tall box"; cylinders are "the least stable of all shapes". Jolt's sample uses a capsule by default (standing: cylinder part 1.35 m, radius 0.3 m; crouching 0.8 m / 0.3 m; inner body shape = 0.9 x), offers Capsule / Cylinder / Box / Compound, sets `mSupportingVolume = Plane(Y, -radius)` ("Accept contacts that touch the lower sphere of the capsule"), speed 6 m/s, jump 4 m/s. Compound character shapes supported since v5.4.0, ScaledShape since v5.2.0. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [CharacterBaseTest.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Samples/Tests/Character/CharacterBaseTest.h); [CharacterBaseTest.cpp](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Samples/Tests/Character/CharacterBaseTest.cpp); [CharacterVirtualTest.cpp](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Samples/Tests/Character/CharacterVirtualTest.cpp); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- Recent CharacterVirtual fixes worth knowing as failure modes: v5.6.0 - speeding up beyond requested speed "when sliding along a wall that was low enough to trigger stair walking yet high enough to not step up completely"; padding sometimes not fully respected; getting stuck when teleported into an area surrounded by too-steep slopes. v4.0.0 - jitter when moving down on an elevator; speeding up when sliding along a wall. — [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)

### Inferences
- The design ideas a Godot-side controller can copy from CharacterVirtual: keep a padding (2 cm) rather than touching geometry; scan predictive contacts ~0.1 m out to compute a slide direction; restrict "supporting" contacts to the lower sphere of the capsule; step = up / forward / down with a second, longer forward test when the per-tick forward distance is tiny; a separate downward "stick to floor" probe; classify ground into four states rather than a boolean.
- Tapered capsule: Jolt lists it as a shape but no fetched page recommends it for characters.

### Gaps
- No Jolt page fetched states an explicit "capsule is better than cylinder for characters because ..." sentence beyond the two quotes above.
- CharacterVirtual.cpp (the algorithm itself) was not read; the description is from the header and Architecture.md only.

## 3. CRUCIAL: Godot's CharacterBody3D does not use Jolt's CharacterVirtual

### Takeaway
Verified from source: with Jolt selected, `CharacterBody3D.move_and_slide` is still Godot scene-side code that calls
`PhysicsServer3D::body_test_motion`; Jolt's character classes are compiled into the engine but no Godot module source
references them. So WalkStairs / StickToFloor / ground states are not available; stairs, ledges and custom snapping must
be written on `body_test_motion` (`move_and_collide`, `test_move`) and space queries. Jolt's `body_test_motion` is
recover (CollideShape with margin, 4 iterations x 0.4) -> binary-search cast -> CollideShape for contacts, with a
deliberate "ignore contacts that do not oppose the motion" filter that is the root of several floor-detection differences.

### Cited Findings
- `PhysicsBody3D::move_and_collide` calls `PhysicsServer3D::get_singleton()->body_test_motion(get_rid(), p_parameters, &r_result)`; `CharacterBody3D::move_and_slide`, `apply_floor_snap` and `_snap_on_floor` all go through `move_and_collide` with `recovery_as_collision = true`. Godot master. — [physics_body_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/3d/physics/physics_body_3d.cpp); [character_body_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/3d/physics/character_body_3d.cpp)
- A GitHub code search for `CharacterVirtual` restricted to `modules/jolt_physics` in godotengine/godot returned exactly one file, `modules/jolt_physics/SCsub`, where `Jolt/Physics/Character/Character.cpp`, `CharacterBase.cpp`, `CharacterVirtual.cpp` (and `Ragdoll.cpp`, `Skeleton*.cpp`) appear only in the list of third-party files to compile. The fetched module files (direct space state, space, body, server) contain no `CharacterVirtual` / `JPH::Character`. Godot master. — [SCsub](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/SCsub); [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)
- `JoltPhysicsDirectSpaceState3D::body_test_motion` (Godot master): errors if called while the space is stepping; `margin = MAX(p_parameters.margin, 0.0001)`; `max_collisions = MIN(requested, 32)`; then (1) `_body_motion_recover`, (2) `_body_motion_cast` from the recovered transform, (3) if hit, or recovered with `recovery_as_collision`, `_body_motion_collide` at `motion * unsafe_fraction`. Result: `travel = recovery + motion * safe_fraction`, `remainder = motion - motion * safe_fraction`, depth = deepest collision depth. — [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)
- Recovery: up to `motion_queries/recovery_iterations` (default 4) passes of CollideShape with `mMaxSeparationDistance = margin` (collector of 32 hits); each pass moves out by `penetration_depth * motion_queries/recovery_amount` (default 0.4) per contact, weighted by the other body's collision priority relative to the average. — [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp); [ProjectSettings.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- The cast is not Jolt's `CastShape`: `_cast_motion_impl` collects up to 1024 bodies whose AABB overlaps the swept AABB, then for each body does a binary search over the motion fraction using `CollideShape` with a custom "motion shape" (the shape extruded along the motion). Step count = `CLAMP(int(log(1000 * motion_length) / ln 2), 4, 16)` ("to achieve millimeter precision, within reason"). Only convex shapes can be cast ("Shape-casting with non-convex shapes is not supported."); in `_body_motion_cast` non-convex shapes of the moving body are skipped. — [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)
- Enhanced internal edge removal is applied in recovery, cast and collide when `motion_queries/use_enhanced_internal_edge_removal` is true (default true): the cast uses `InternalEdgeRemovingCollector` with `CollideWithAll` + `CollectFaces`; recover/collide use `NarrowPhaseQuery::CollideShapeWithInternalEdgeRemoval`. — [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)
- The contact filter, verbatim from Godot master / 4.7-stable `JoltQueryCollectorMotion::AddHit`: "Ignore hits that don't oppose the motion direction. This is a deliberate divergence from the Godot Physics reference implementation (which does not do this type of filtering) and is known to cause issues. However, not having this results in a problematic amount of ghost collisions with `move_and_slide`, for reasons that are still unclear as of writing this." Condition: `if (direction.dot(normal) >= -CMP_EPSILON) return;` (only when motion length > 0); hits with `penetration_depth + margin <= 0` are also dropped. — [jolt_query_collectors.h](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_query_collectors.h); [4.7-stable copy](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/modules/jolt_physics/spaces/jolt_query_collectors.h)
- In 4.4-stable and 4.6-stable the same `direction.dot(normal) >= -CMP_EPSILON` test sat after collection inside `_body_motion_collide`; 4.7 moved it into the collector. — [4.6-stable jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/4.6-stable/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp); [4.4-stable copy](https://raw.githubusercontent.com/godotengine/godot/4.4-stable/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)
- Issue #117857 (closed, 4.7 milestone, fixed by PR #118155): with Jolt on 4.6, `move_and_collide()` "sometimes returned null even though a collision existed", worst when wedged between converging floor and ceiling and with small deltas (also at 120 Hz physics); only with Jolt. jrouwe: the problem is "inside the `JoltPhysicsDirectSpaceState3D::body_test_motion` function and not inside Jolt"; mihe: "that `direction.dot(normal)` check is highly questionable"; "`move_and_collide` suffers because it's used within `move_and_slide`". — [godot#117857](https://github.com/godotengine/godot/issues/117857)
- Issue #104969 (open; 4.4.1): with Jolt "no slide collisions are reported when moving parallel to a surface", so floor contacts from `move_and_slide` differ from Godot Physics. mihe: there are "a few discrepancies between the two implementations of `PhysicsServer3D::body_test_motion`" affecting "`is_on_floor`, `is_on_ceiling` and `is_on_wall`"; cause is the code where "if a contact normal is deemed to not obstruct the direction of movement, that contact is discarded"; "Removing this code will likely fix the issue here, but will cause a significant amount of ghost collisions". — [godot#104969](https://github.com/godotengine/godot/issues/104969)
- Issue #114605 (open; 4.5.1, 4.6 beta 2): with Jolt `body_test_motion` returned false with a result object and true without one; jrouwe traced it to the normal check in `_body_motion_collide` that "causes an early out", and said "I'm not going to attempt to fix this logic as it's quite delicate". — [godot#114605](https://github.com/godotengine/godot/issues/114605)

- Issue #112315 (open; Jolt, 4.4 / 4.5.1 / 4.6 dev): calling `apply_floor_snap` with a small positive Y velocity onto a moving AnimatableBody3D makes the next `move_and_slide` add the platform velocity to the character ("catapulting"); reporter's workaround: zero `velocity.y` each physics frame while on the floor. No maintainer comment. — [godot#112315](https://github.com/godotengine/godot/issues/112315)
- CharacterBody3D defaults (Godot master class reference): `safe_margin` 0.001 ("Extra margin used for collision recovery ... - Jolt capsule build rules in Godot: radius > 0, height > 0, and "height must be at least double that of its radius". — [jolt_capsule_shape_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/shapes/jolt_capsule_shape_3d.cpp)
- Godot docs: "Switching the physics engine from the default GodotPhysics to Jolt should make cylinder collision shapes more reliable"; with GodotPhysics, box or capsule is recommended for characters ("Capsule collision shapes ... their shape can make precision platforming more difficult"). — [troubleshooting_physics_issues.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/troubleshooting_physics_issues.rst)
- Ghost collisions across separate bodies are not removed: "neither the active edge detection nor enhanced internal edge removal apply when dealing with ghost collisions between two different bodies." The Godot docs' general advice for bumps across tiles is a single composite collider. — [using_jolt_physics.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/using_jolt_physics.rst); [troubleshooting_physics_issues.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/troubleshooting_physics_issues.rst)
- Issue #88476 (open; first reported on 4.2.1, commenters on 4.4 beta/rc): CharacterBody3D with CylinderShape3D against a ConcavePolygonShape3D reports wildly wrong collision results (depth 0.244 for a 0.25 radius cylinder from slight movement); a commenter says "This occurs on Jolt also". — [godot#88476](https://github.com/godotengine/godot/issues/88476)
- Cost: issue #93184 (open): many CharacterBody3D in a production level; reported `move_and_collide()` around 30-40 microseconds with Godot Physics, "Jolt was faster", one later figure 18.6 microseconds; a custom step-move script "takes approximately 20x longer on average than move_and_slide()" (clayjohn) with `move_and_collide` calls spiking from 160 to over 1700 per frame; advice given: cap `move_and_collide` calls per tick per entity; "Static level geometry should generally always use concave collision shapes (trimesh), not convex" (Calinou); one trimesh instead of many convex shapes was much faster. — [godot#93184](https://github.com/godotengine/godot/issues/93184)

### Inferences
- Recovery strength: 4 iterations at 0.4 removes about 1 - 0.6^4 = 87% of an overlap per `body_test_motion` call (arithmetic on the cited defaults), so deep overlaps (e.g. after a shape swap for crouch) take more than one tick to clear.
- Because contacts whose normal does not oppose the motion are dropped, a purely horizontal test over a flat floor reports no floor contact under Jolt. A custom controller should detect ground with its own downward motion test or shape cast every tick rather than rely on slide collisions from horizontal motion; the same applies to wall checks when moving parallel to the wall.
- A step-up built from several `move_and_collide(test_only)` calls (up, forward, down) multiplies query cost by the number of calls per tick per character; #93184 shows this is the first thing that hurts with many characters.
- A capsule has no convex-radius margin under Jolt, so its query normals are not affected by `collision_margin_fraction`; box/cylinder/convex query shapes are.
- For rotating platforms the engine applies only the linear velocity at the contact point per tick (#102763), so a custom controller that must ride rotating platforms needs its own correction.

### Gaps
- One-way collisions in 3D under Jolt: no source found.
- "Jitter on edges" under Jolt specifically: no dedicated issue was read; only the ghost-collision and floor-detection issues above.
- PR #118155 and PR #110102 themselves were not opened; their content is known only from the issue pages.
- Whether Godot plans to expose CharacterVirtual: no source found.

## 4. Godot Jolt integration specifics (settings, differences, versions, status)

### Takeaway
Jolt has been built into Godot since 4.4 (experimental in 4.4 and 4.5; label removed and made the default for new
projects in 4.6). There are 32 project settings under `physics/jolt_physics_3d/` in 4.6 / 4.7 / master. Godot always runs
Jolt with 1 collision step per physics tick. The only documented feature gap against the old extension is the Jolt-specific
joint nodes.

- Single-body joints: Godot Physics always behaves as if the body were `node_a`; Jolt behaves as if it were `node_b` with `node_a` the world (toggle: `joints/world_node`).
- Collision margins: Godot Physics ignores `Shape3D.margin`; Jolt uses it as a convex radius that shrinks then re-inflates (no size change).
- Baumgarte: in Godot Physics it "works like a spring" and can overshoot; in Jolt it is applied to position only, "cannot overshoot but it may take longer to resolve the penetration".
- Ghost collisions: active edge detection + enhanced internal edge removal, as in section 1; neither works across different bodies.
- Memory: Jolt pre-allocates a stack allocator (temporary memory buffer size).
- Ray-cast `face_index` is -1 unless `queries/enable_ray_cast_face_index` is on.
- Kinematic RigidBody3D (`FREEZE_MODE_KINEMATIC`) does not report contacts with static/kinematic bodies unless `simulation/generate_all_kinematic_contacts` is on.
- Contact impulses from `get_contact_impulse()` are estimated ahead of time; accurate only when the two bodies touch nothing else.
- Area3D gets overlap signals for SoftBody3D under Jolt (not under Godot Physics).
- WorldBoundaryShape3D has a much smaller effective size under Jolt (setting above, default 2000).
- Extension -> built-in: settings moved from `physics/jolt_3d` to `physics/jolt_physics_3d` with renames (e.g. `collisions/use_shape_margins` -> `collisions/collision_margin_fraction`, 0 = off; `kinematics/recovery_iterations` -> `motion_queries/recovery_iterations`; `kinematics/recovery_amount` -> `motion_queries/recovery_amount`; `solver/velocity_iterations` -> `simulation/velocity_steps`; `solver/position_iterations` -> `simulation/position_steps`; `collisions/areas_detect_static_bodies` -> `simulation/areas_detect_static_bodies`; `collisions/report_all_kinematic_contacts` -> `simulation/generate_all_kinematic_contacts`; `queries/use_legacy_ray_casting` removed).
- The extension's joint nodes (JoltPinJoint3D, JoltHingeJoint3D, JoltSliderJoint3D, JoltConeTwistJoint3D, JoltGeneric6DOFJoint) "have not been included in the Jolt module". The extension is "in maintenance mode".

## 5. Traversal queries in Godot under Jolt (ray, shape cast, collide, rest info)

### Takeaway
Under Jolt, `intersect_ray` is a closest-hit Jolt ray cast; `cast_motion` is a per-body binary search (not a true
sweep) that ignores anything already overlapping at the start and returns safe/unsafe fractions about 1 mm apart;
`collide_shape` / `get_rest_info` / `intersect_shape` are Jolt CollideShape calls where `margin` becomes Jolt's
max-separation distance. Trimesh shapes are hollow and one-sided unless `backface_collision` is enabled, which is the
most common reason a ledge / climb probe "misses".

### Cited Findings
- All direct-space queries error if called while the space is stepping ("... must not be called while the physics space is being stepped") and flush pending objects first. Godot master. — [jolt_physics_direct_space_state_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_physics_direct_space_state_3d.cpp)

- Thread note: issue title "PhysicsDirectSpaceState*D and PhysicsDirectBodyState*D are subject to race conditions when physics server runs on separate thread" (#109554, closed) appeared in the issue search; the page itself was not opened. — [godot#109554](https://github.com/godotengine/godot/issues/109554)

### Inferences
- Probe recipe that follows from the code: use `cast_motion` (or a ShapeCast3D with a non-zero target) for "where does it first touch", then `get_rest_info` / `collide_shape` at the unsafe position for point and normal - this is what ShapeCast3D itself does. A zero-length cast returns nothing by design, so "is this space free" must be `intersect_shape` / `collide_shape`, not `cast_motion`.
- `cast_motion` starting in penetration ignores the bodies it starts inside, so a forward probe that starts inside a wall passes through that wall silently. Start probes from a known-free pose (inside the character's own capsule volume) and exclude the character's RID.
- Against one-sided trimesh, a static overlap test only registers when the query shape actually intersects a triangle whose front faces it; a shape fully inside a closed trimesh volume, or behind a one-sided wall, reads as free. For ledge-top and clearance checks on trimesh level geometry, sweep (do not overlap) from the open side, or use convex colliders / `backface_collision` on traversal geometry.
- For downward ledge / floor rays over trimesh, a thin sphere `cast_motion` is more robust than a ray on shared edges (issue #124689 and Jolt's own advice); cost is higher (binary search of CollideShape calls per candidate body).
- The binary search costs up to 16 CollideShape evaluations per candidate body plus 1-2 pre-checks, so long casts through many AABBs are far more expensive than a ray; keep traversal sweeps short and layer-filtered.
- `queries/use_enhanced_internal_edge_removal` is off by default, so normals from `collide_shape` / `get_rest_info` on trimesh seams are only protected by the (50 degree) active-edge rule; `body_test_motion` has it on by default. Normals from the two families can therefore differ at the same spot.

### Gaps
- Per-frame query budgets (how many rays / shape casts per tick are affordable, especially on phones): no source found. Only data points: `move_and_collide` about 18.6-40 microseconds on unspecified desktop hardware (#93184).
- No fetched source states whether `intersect_shape` / `collide_shape` honour back faces for one-sided trimesh beyond the issue comments above; the shape-instance code that applies `backface_collision` (and gives Area3D shapes back-face collision: `has_back_face_collision = is_area()` in jolt_shaped_object_3d.cpp) was only partly read.

## 6. Ragdolls: Jolt's ragdoll system versus what Godot exposes

### Takeaway
Jolt has a complete ragdoll layer (RagdollSettings / Ragdoll / SkeletonPose / SkeletonMapper, mass stabilisation,
parent-child collision filtering, drive-to-pose by kinematics or by constraint motors). Godot compiles it but does not use
it: Godot ragdolls are PhysicalBone3D bodies joined by ordinary PhysicsServer3D joints, which under Jolt become Jolt
constraints (ConeTwist -> SwingTwistConstraint). An active ragdoll in Godot therefore has to be built from 6DOF joint
springs/motors or from forces, not from `DriveToPoseUsingMotors`.

### Cited Findings
Jolt
- `RagdollSettings`: skeleton + one `Part` per joint (a `BodyCreationSettings` plus `mToParent` constraint settings) + `mAdditionalConstraints` (non parent-child, since v4.0.0). `Stabilize()`; `DisableParentChildCollisions(jointMatrices, minSeparation)` creates a `GroupFilterTable`, gives each body a sub-group = joint index, disables collision between each joint and its parent, and (if a pose is given) between any parts that overlap in that pose; each ragdoll instance needs a unique GroupID. `CalculateConstraintPriorities` (v5.5.0) gives joints near the root higher priority. — [Ragdoll.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.h); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- `Stabilize()` source comments: "Based on: Stop my Constraints from Blowing Up! - Oliver Strunk (Havok). Do 2 things: 1. Limit the mass ratios between parents and children 2. Increase the inertia of parents so that they're bigger or equal to the sum of their children". — [Ragdoll.cpp](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.cpp)
- `Ragdoll` run-time: `AddToPhysicsSystem`, `SetPose` (instant teleport via SetPositionAndRotation), `GetPose`, `ResetWarmStart` (use after SetPose so last frame's impulses are not applied), `SetLinearAndAngularVelocity`, `AddImpulse`, `GetRootTransform`, `IsActive`. — [Ragdoll.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.h)
- `DriveToPoseUsingKinematics(pose, dt)`: "setting velocities on each of the bodies so that it will reach inPose in inDeltaTime"; implementation calls `BodyInterface::MoveKinematic` for every body. — [Ragdoll.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.h); [Ragdoll.cpp](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.cpp)
- `DriveToPoseUsingMotors(pose)`: for each body's parent constraint, a SwingTwistConstraint gets swing and twist motors set to `EMotorState::Position` and `SetTargetOrientationBS(joint rotation)`; a HingeConstraint (supported since v5.4.0) gets `Position` + `SetTargetOrientationBS`; other constraint types assert "Constraint type not implemented!". A second overload (v5.6.0) takes previous and current pose and dt and drives position and velocity. — [Ragdoll.cpp](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Ragdoll/Ragdoll.cpp); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- SwingTwistConstraint: "a specialized constraint for humanoid ragdolls"; "approximates the shoulder joint of a human"; limits `mNormalHalfConeAngle`, `mPlaneHalfConeAngle`, `mTwistMinAngle`, `mTwistMaxAngle` (twist within [-pi, pi]); `mMaxFrictionTorque` (friction when not powered); separate swing and twist motor settings. — [SwingTwistConstraint.h](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/Constraints/SwingTwistConstraint.h); [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Motors: states Off / Velocity / Position (/ PositionAndVelocity); force is proportional to `stiffness * (target - current) + damping * (target_velocity - current_velocity)`; spring modes StiffnessAndDamping, mass-normalised, or FrequencyAndDamping. "Valid frequencies are in the range (0, 0.5 * simulation frequency]"; "For a 60 Hz physics simulation, 20 is a good value for a stiff spring ... 2 is good for a soft spring"; damping 1 = critical; torque/force limits default to +-FLT_MAX and "If your motor doesn't seem to do anything, chances are that you have set the value too low". — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Samples ("Rig" category): kinematic ragdoll interacting with dynamic objects; humanoid ragdoll driven by motors matching a sprint animation in local space; skeleton mapper (animation on a high-detail skeleton mapped to a low-detail ragdoll skeleton, drive motors, map back); 160 ragdolls in a pile; 160 ragdolls driven to a death pose ("This gives the ragdolls 'stiffness'"). SkeletonMapper added in v2.0.0. — [Samples.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Samples.md); [ReleaseNotes.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/ReleaseNotes.md)
- Step listeners "can be used to do work that needs to be done at the beginning of each step, e.g. set velocities on ragdoll bodies". — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Constraints are solved in the velocity domain and drift is fixed by the position solver; breakable joints are done by reading total lambda after a step and disabling the constraint. — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Horizon Forbidden West (GDC 2022 notes): Guerrilla moved from 30 Hz to "two steps of 60 Hz while spending less time on the physics update"; run-time memory -25%, physics asset size -30%, executable -12%; the Slitherfang boss case went from avg 3.3 ms / 21 ms spike to avg 2.1 ms / 10 ms spike, and "the ragdoll of the Slitherfang is much more stable due to the higher update frequency". — [GDC 2022 notes PDF](https://jrouwe.nl/architectingjolt/ArchitectingJoltPhysics_Rouwe_Jorrit_Notes.pdf)

Godot
- Godot ragdoll = `PhysicalBoneSimulator3D` (parent, controls simulation; `physical_bones_start_simulation(bones)` can simulate only a listed subset; `physical_bones_stop_simulation`; collision exceptions) + `PhysicalBone3D` children. The editor's "Create Physical Skeleton" generates bones, shapes and pin joints. Joint types on PhysicalBone3D: None, Pin (default; "Leads to 'crumpling' of the bones, so it's recommended to use other joint types"), Cone (shoulders, hips, neck; advice: swing span 20-90 degrees, twist span 20-45 degrees), Hinge (elbows, knees; enable Angular Limit), Slider, 6DOF. "For each PhysicalBone3D the engine needs to simulate, there is a performance cost"; remove tiny and utility bones (one bone for a hand). — [ragdoll_system.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/ragdoll_system.rst); [PhysicalBoneSimulator3D.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/PhysicalBoneSimulator3D.xml); [physical_bone_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/3d/physics/physical_bone_3d.cpp)
- PhysicalBone3D creates its joint through generic PhysicsServer3D calls (`joint_make_pin`, cone-twist / hinge / slider / 6DOF params). To be hit by ray casts the simulator must be active and the bone id valid. — [physical_bone_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/3d/physics/physical_bone_3d.cpp); [PhysicalBone3D.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/PhysicalBone3D.xml)
- Under Jolt, a cone-twist joint is a `JPH::SwingTwistConstraint` (twist min/max = -/+ twist span, `mNormalHalfConeAngle` = swing span); bias / softness / relaxation print "not supported when using Jolt Physics. Any such value will be ignored". The Jolt joint class has swing/twist velocity motors behind "jolt param / jolt flag" setters. — [jolt_cone_twist_joint_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/joints/jolt_cone_twist_joint_3d.cpp)

The file also has Jolt-only extras (limit spring frequency/damping, spring-by-frequency flags). — [jolt_generic_6dof_joint_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/joints/jolt_generic_6dof_joint_3d.cpp)
- The module compiles `Ragdoll.cpp`, `SkeletonMapper.cpp`, `SkeletonPose.cpp` only as third-party sources. — [SCsub](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/SCsub)

### Inferences
- No Godot API reaches `Ragdoll::DriveToPoseUsingMotors`, `Stabilize` or `DisableParentChildCollisions`; the equivalents must be done by hand: (a) mass ratios and inertia chosen manually along the chain (Jolt's own stabiliser limits parent/child mass ratio and raises parent inertia), (b) collision exceptions between neighbouring bones, (c) active ragdoll via PhysicalBone3D 6DOF joints with angular springs (-> Jolt Position motors) driven by setting the spring equilibrium to the animated local rotation each tick, or via external torques.
- Kinematic "driven" ragdoll parts in Godot correspond to Jolt's `MoveKinematic` path (kinematic bodies are moved that way by the module), i.e. the same mechanism as `DriveToPoseUsingKinematics`, if bones are kept kinematic and fed animation transforms.
- Stability levers that are actually available under Jolt in Godot: physics tick rate (60 Hz, which is what Jolt and HFW target), `simulation/velocity_steps` (10) and `position_steps` (2), damping per bone, joint limits (cone 20-90 / 20-45 degrees), fewer bones.

## 7. Performance and robustness guidance (timestep, scale, meshes, platforms, tunnelling)

### Takeaway
Jolt is tuned for SI units, dynamic objects 0.1-10 m, speeds up to 500 m/s, 60 Hz with one collision step, and a world
within about 5 km of the origin in single precision. Tunnelling comes from discrete motion of small/fast bodies, hollow
trimesh, and exceeding the body-pair / contact limits; kinematic platforms should be moved by velocity (MoveKinematic),
which is what Godot does.

### Cited Findings
- "the physics simulation works best if you use SI units (meters, radians, seconds, kg). In order for the simulation to be accurate, dynamic objects should be in the order [0.1, 10] meters long, have speeds in the order of [0, 500] m/s and have gravity in the order of [0, 10] m/s^2. Static object should be in the order [0.1, 2000] meter long." — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- "If all simulation takes place within roughly 5 km from the origin, floating point precision is accurate enough." Double precision (`JPH_DOUBLE_PRECISION`) keeps accuracy far from the origin at a cost of 5-10%; "There are a lot of 'epsilons' in the code that have been tuned for objects of sizes/speeds as described". — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- "In general, the system is stable when running at 60 Hz with 1 collision step." Godot runs exactly that by default (60 ticks, `Update(step, 1, ...)`). — [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md); [jolt_space_3d.cpp](https://raw.githubusercontent.com/godotengine/godot/master/modules/jolt_physics/spaces/jolt_space_3d.cpp); [ProjectSettings.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- Godot caps under Jolt: linear velocity 500 m/s, angular 47.12 rad/s, 10240 bodies, 65536 body pairs, 20480 contact constraints (past the last two "collisions will randomly be ignored while bodies pass through each other"). — [ProjectSettings.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)
- Tunnelling causes and remedies (Godot docs): enable Continuous CD on the RigidBody; thicker static colliders; enlarge the fast object's shape with speed; raise physics ticks per second (multiples of 60; "increases CPU utilization and may not be viable for mobile/web platforms"). — [troubleshooting_physics_issues.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/troubleshooting_physics_issues.rst)
- Trimesh: hollow; "Physics bodies that are small have a chance to clip through this shape when moving fast"; intended for static bodies. Jolt: avoid dynamic meshes ("fairly expensive to simulate"). Jolt mesh edges: shared edges and no T-junctions are needed for internal edge removal to work. — [ConcavePolygonShape3D.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ConcavePolygonShape3D.xml); [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Level geometry: one trimesh instead of many convex shapes was far faster for many characters (reports of about 100 FPS -> about 700 FPS in one user's level); "breaking things up into reasonably large sections is the best" (AThousandShips). — [godot#93184](https://github.com/godotengine/godot/issues/93184)
- Kinematic bodies and sensors against big static meshes are expensive if they generate contacts ("you can end up wasting a significant amount of CPU performance and memory without realizing it"). — [using_jolt_physics.rst](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/physics/using_jolt_physics.rst); [Architecture.md](https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Docs/Architecture.md)
- Tick-rate cost data points: a phone report in #93184 (Adreno 740, S23+) - 160 physics ticks gave 12-17 FPS, 60 ticks held 60 FPS; desktop Jolt went from 300+ FPS at 60 Hz to about 50 FPS at 240 Hz in the same many-character scene. — [godot#93184](https://github.com/godotengine/godot/issues/93184)
- Small deltas made the Jolt `body_test_motion` contact filter fail more often before 4.7 (120 Hz, or calling from `_process`). — [godot#117857](https://github.com/godotengine/godot/issues/117857)
- Speculative contacts (0.02 m) prevent tunnelling/penetration for RigidBody3D during simulation; too high "may result in ghost collisions". — [ProjectSettings.xml](https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/ProjectSettings.xml)

### Inferences
- A CharacterBody3D is not protected by Jolt's CCD setting; its protection against tunnelling is the sweep inside `body_test_motion` (binary search over the swept shape against candidate bodies found by swept AABB), which holds as long as the candidate is found - but hollow one-sided trimesh can still be entered from behind, and the cast ignores nothing at the start for body motion (`p_ignore_overlaps = false`), relying on recovery instead.
- Keep physics at 60 Hz on phones; step-up logic that multiplies motion tests is the cost to watch, not Jolt's simulation.
- A map larger than about 5 km from origin needs either origin shifting or a double-precision engine build (which the Jolt module supports).
